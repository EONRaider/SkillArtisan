# Changelog

All notable changes to SkillArtisan are documented here. Format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/); versioning follows [Semantic Versioning](https://semver.org/), interpreted for this project as:

- **Major version bump (1.0.0 → 2.0.0)** marks a v-stage boundary, not just a breaking change — v1 → v2 is the deliberate release split (see the master spec's "Build Stages → Plugin Files → Release Scope"), not an accident of semver discipline.
- **Minor version** for new capability within a stage that doesn't break existing usage (e.g. adding cross-agent evaluation as an opt-in mode within v1).
- **Patch version** for fixes — corrected patterns, tightened validation, documentation accuracy.

## [Unreleased]

### Deferred, not forgotten
- **Best-in-Market Scorecard full run** (master spec's "Best-in-Market Scorecard" section, companion prompt's "The Best-in-Market Scorecard (full run)"). Both source documents gate this explicitly behind "if asked to run it" — it requires building a 12-20 skill benchmark corpus, cloning and running `daymade/claude-code-skills` and `tripleyak/SkillForge` as live comparison arms alongside Anthropic's shipped `skill-creator`, and dozens of real `claude -p` with/without-skill benchmark runs per arm. Not run in this session; nobody asked for it yet, and the master spec is explicit that "best in market" must not be claimed anywhere until it has been. Axis 1 (checklist compliance) can now be scored against the *full* Gap Table rather than the v1-scoped subset, since v2 is shipped — that's the one thing this release changes about the scorecard's own preconditions.
- **Row 32 (contribute-back / auto-PR mode) beyond planning.** `scripts/audit.py pr-plan` produces an additive-only-changes plan from a third-party skill's audit findings but deliberately never calls `gh pr create` itself — the master spec requires explicit user confirmation before any PR opens against a repo this plugin doesn't own, which a script can't obtain on its own. This was always scoped as optional and lower priority than items 1-5; it's open on purpose, not a miss.
- `creating-skills` has no `evals/evals.json` of its own yet — real content for the eval engine to run against would need it, and `scripts/audit.py report` (run against `creating-skills` itself as part of this release's own dogfooding) correctly flags this as a FAIL. Not part of either stage's stated scope, but worth tracking since the tool now surfaces its own gap.
- **The live before/after regression benchmark** (audit item 4) was documented as an `eval_loop.py` workflow but not actually executed against `skill-creator` in this session — that would mean spawning real with/without-skill subagent runs against a third-party plugin this project doesn't own just to demonstrate the workflow, which wasn't asked for and wasn't worth the cost for a demonstration. The checklist audit, upgrade-vs-rebuild decision, and institutional-knowledge safeguard against `skill-creator` were all run for real (see below); the regression-benchmark step of that same acceptance criterion is documented, not demonstrated end-to-end.
- **Multi-model verification of `creating-skills` itself** (Synthesized Checklist item "Multi-model tested: Haiku, Sonnet, Opus") wasn't re-run in this session — the guidance requiring it is in place (`SKILL.md`'s "Testing and evaluating" section), but that's a process requirement being taught, not a claim that `creating-skills` was itself put through a fresh three-model smoke pass during this v2 build.

## [2.0.0] - 2026-08-16

Stages 5-6 of the master spec, per the companion build prompt (Prompt B; kept locally rather than in this repo, matching Prompt A's precedent). Read the actual v1 code and the `[1.0.1]` dogfooding entry before designing Stage 6's audit heuristics, per the master spec's own instruction — `scripts/audit.py` reuses `validate.py` and `security_scan.py`'s functions directly rather than re-deriving equivalent checks, and never treats gitleaks/pattern-check absence as a hard error the way `[1.0.1]`'s fix treated silent test collisions as unacceptable: unavailable tooling reports `MANUAL`, not a false PASS or a crash.

### Added
- **Lifecycle framing** (`references/lifecycle.md`, row 14): capability-uplift vs. encoded-preference classification, a scored 0-10 timelessness threshold (≥7 durable), re-benchmarking triggers tied to model upgrades, and a "last verified against model X" convention. `creating-skills/SKILL.md` classifies itself as a working example — encoded-preference, timelessness 9/10, last verified against claude-sonnet-5 (2026-08) — in a new "Lifecycle" section, not just in the reference file.
- **Audit mode** (`scripts/audit.py`, rows 31-32): a `report` subcommand that runs a 21-item checklist pass against an existing skill (frontmatter validity, security-scan cleanliness, evals presence, body-size limits, reference depth/TOC, content hygiene, lifecycle classification, and a heuristic degrees-of-freedom proxy — each PASS/FAIL/WARN, plus four items marked `MANUAL` where no pattern can substitute for a human/LLM read: coherent-unit scoping, multi-model testing, description-optimizer usage, and inline-vs-fork correctness); an upgrade-vs-rebuild decision gate that defaults to upgrade-in-place and only recommends rebuild for a named condition (frontmatter and description both failing together, a capability-uplift skill under the 7/10 timelessness bar, or body size more than double the limit); an institutional-knowledge safeguard that flags `##` section headings with no obvious checklist counterpart for an explicit keep/fold-in/discard decision, never a silent drop; a `bulk` subcommand that runs the same report across every skill found under a directory and prints a collective table (reuses `_common.find_skill_dirs`, promoted out of `dedup_search.py` so both scripts share one implementation rather than two copies); and an optional `pr-plan` subcommand (row 32, lower priority than the rest) that prints an additive-only-changes contribution plan for a third-party skill without ever calling `gh` itself. Regression benchmarking (item 4) is documented as an `eval_loop.py` before/after workflow in `SKILL.md`'s new "Auditing existing skills" section rather than reimplemented — the same division of labor the eval engine already uses, since a standalone script can't spawn the subagents that actually run it.
- **Verified against a real third-party skill, not just a stub.** `audit.py report` was run against Anthropic's actual shipped `skill-creator` (`~/.claude/plugins/marketplaces/claude-plugins-official/plugins/skill-creator/skills/skill-creator` on the machine this was built on) — confirmed a checklist pass rate consistent with the master spec's own Confidence Notes (no frontmatter validation, no security scan, no lifecycle classification, evals present but no gerund-form naming), decision `upgrade-in-place` (its gaps are structural additions, not a broken triggering-logic rebuild case), and real institutional-knowledge candidates surfaced from its actual section headings ("Communicating with the user," "Report structure," "Advanced: Blind comparison," among others). `audit.py bulk` was run against three dummy skills of deliberately varying quality (a clean encoded-preference skill with evals, a mediocre skill with Windows paths and unexplained bare directives, and a broken skill with a name/directory mismatch and no usable description) and produced the expected spread: two `upgrade-in-place`, one `rebuild` — confirming the decision gate's named conditions actually discriminate rather than defaulting to one branch regardless of input. Both dummy fixtures and their location were scratch material for this verification pass, not shipped as part of the plugin.
- **Full Synthesized Checklist walkthrough**, now unrestricted by the v1/v2 exclusions the master spec scoped out at the v1 release checkpoint — every item checked against the complete v1+v2 repo and its file(s) named directly (no separate tracking document; the checklist itself lives in the master spec, not duplicated here).

### Changed
- `scripts/dedup_search.py`'s `find_skill_dirs` moved to `scripts/_common.py` (`audit.py bulk` needed the identical directory-discovery logic; the `scripts/`-discipline rule this plugin already enforces on authored skills — one implementation, not two copies that drift — applies to its own `scripts/` directory too).
- `README.md`'s release-scope section and comparison table updated to reflect v2 as shipped rather than planned.

### Fixed
- **`scripts/description_optimizer.py`: trigger-eval self-collision when testing description changes for an already-installed skill.** Found while dogfooding v1 on a real project skill (`drafting-changelog-entries`, added to this repo's own `.claude/skills/` as the v1 dogfood exercise — not part of the shipped plugin). The per-query synthetic test copy gets a randomized name specifically so it won't collide with anything real, but if the skill under test is *also* sitting at its real, natural name in the same project with a near-identical description, the model tends to reach for the naturally-named real one instead of the synthetic candidate — and the harness only counts a trigger against the synthetic name, so every one of those turns silently reads as a miss. Confirmed directly: the exact same query/description pair scored 0/3 with the real skill present, 1/3 with it hidden. `run_eval` now moves the real `.claude/skills/<name>/` aside for the duration of the run and restores it afterward (`try`/`finally`). Verified the restore fires on normal completion; the crash-safety property for an abnormal exit mid-run rests on the `try`/`finally` construct itself rather than on having reproduced an actual kill during testing — worth a closer look before relying on it for anything long-running. Only matters for improving an existing skill — a brand-new skill has nothing installed yet to collide with.

## [1.0.0] - 2026-08-15

Stages 1-4 of the master spec, built and verified against a live `claude -p` session and a real `gitleaks` install (not just documentation) — per the companion build prompt (Prompt A; kept locally rather than in this repo, not published alongside the plugin).

### Added
- **Eval engine**, ported from `skill-creator` with no loss of capability: parallel with/without-skill subagent runs from a clean context, `agents/grader.md`/`comparator.md`/`analyzer.md` subagent roles, the `evals/evals.json` test-case format, benchmark aggregation with mean/stddev/delta (`scripts/eval_loop.py`), an analyst pass flagging always-pass/always-fail assertions, blind A/B comparison, the HTML eval-viewer (`eval-viewer/generate_review.py` + `viewer.html`, Outputs/Benchmark tabs, `--static` mode, `--previous-workspace` diffing), and the trigger-eval review template (`assets/eval_review.html`).
- **Description optimizer** (`scripts/description_optimizer.py`): 60/40 train/validation split (shuffled once, fixed across iterations), 3x runs per query against a 0.5 trigger-rate threshold, up to 5 iterations, selection by validation pass rate. Fixed two real bugs found while verifying this against a live session: the trigger-registration path (`.claude/skills/<name>/SKILL.md`, not `.claude/commands/` — the latter registers as a slash command and never appears in `available_skills`) and a concurrency race between simultaneously-launched `claude -p` subprocesses sharing one project root (fixed with a small launch stagger).
- **Named trial-count presets** (`--smoke`/`--reliable`/`--regression`) and **CI gating** (`--ci --threshold`) in `scripts/eval_loop.py`.
- **The Decision Gate**, in `creating-skills/SKILL.md`: artifact-type routing (skill vs. CLAUDE.md vs. AGENTS.md vs. MCP vs. subagent vs. plugin vs. DESIGN.md), a dedup check with match-confidence routing (`scripts/dedup_search.py` — ≥80% use-existing / 50-79% improve-existing / <50% create-new / compose), and an inline-vs-fork architecture guide with worked examples.
- **`scripts/validate.py`**: wraps the official `skills-ref` validator (verified directly against the real tool) plus a Claude-specific layer — reserved-word check, gerund-naming suggestion, extended-field classification, and path-reference existence checking. `--suggest-compatibility` auto-populates the `compatibility` field per target surface.
- **`references/surface-matrix.md`**: all five surfaces (Claude Code, Claude.ai, Cowork, Claude Tag, Messages API) plus the generic cross-vendor default, extended Claude Code frontmatter fields, and the plugins-cache-vs-source-path gotcha.
- **`scripts/security_scan.py`**: two-tier gitleaks (default gate) + pattern-checks (`--verbose`, educational layer) scanner, verified against a real gitleaks install — including the unsafe-command-interpolation check (row 38) and the blocking-interactive-input / no-documented-cli script-design checks. SHA256 content-hash tamper detection (`.security-scan-passed`, atomic write) blocks packaging on any post-scan edit. `.skillignore`-based packaging exclusion, enforced (not just documented) by `--package`.
- **`references/security-checklist.md`**, **`references/sanitization-checklist.md`** (the AI semantic read-through step, required of the author before publishing their own skill), and **`references/script-design.md`**.
- **`references/writing-philosophy.md`** and **`references/frontmatter-spec.md`**: imperative voice, explain-the-why, coherent-unit scoping, the three-tier degrees-of-freedom heuristic, content hygiene, and the canonical six-field frontmatter spec with the pushy+imperative description technique.
- Plugin manifest (`.claude-plugin/plugin.json`), plugin-root `.skillignore` and `.gitignore`. Verified against `claude plugin validate --strict`, which caught two real issues fixed before release: the `skills` field needed `"./"` (skill directories sit directly at plugin root, not nested under a `skills/` folder) rather than pointing at `creating-skills` itself, and `agents/*.md` needed proper `name`/`description` frontmatter — Claude Code auto-discovers a plugin's `agents/` directory as real invokable subagent definitions, not just reference prose, so `grader`/`comparator`/`analyzer` are now genuinely invocable via the Task tool's `subagent_type`, not only readable as instructions.

### Deliberately out of scope for v1 (not missed — see the master spec's release-split rationale)
- Row 14: lifecycle framing (capability-uplift vs. encoded-preference, timelessness scoring)
- Row 31: bulk/whole-library audit mode
- Row 32: contribute-back / auto-PR mode

All three ship in v2 (Stage 5-6, Prompt B), after v1 has been dogfooded on real skills.
